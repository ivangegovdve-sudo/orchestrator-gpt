What it can answer

The tool list is bounded, read-only and explicit about unknowns. A missing field is not silently converted into a favorable ranking.

dashboard_benchmarks

Read published Artificial Analysis, Design Arena and OpenRouter benchmark observations with exact provenance; upstream failures stay explicit.

dashboard_source_health

Report source freshness, collector failures and available public routes.

dashboard_model_economics

Compare OpenRouter, Groq, Cerebras and Sail on exact price points, discounts, context, modality, tools, performance, availability and retirement risk. Conditions stay attached to every point.

dashboard_catalogue

List all acquired provider identities, including unpriced rows, with exact native price points, source populations and explicit acquisition gaps.

dashboard_price_comparison

Compare exact matching price points across Crazyrouter and OpenRouter, refusing incompatible units or conditions instead of inventing a conversion.

dashboard_resolve_model

Return a bounded fallback list that satisfies every explicit provider, capability and lifecycle constraint.

dashboard_model_status

Diagnose an exact model id, separating last seen from the latest complete check that could have observed its absence.

dashboard_free_models

Find currently listed, genuinely free models. Rate-limited free routing and unknown prices are kept separate.

dashboard_whats_changed

Surface appearances, disappearances, deprecations, price movement and models that stopped being free. The result is partial when the archive cannot establish full coverage.

dashboard_usage_leaders

Rank public model usage while keeping rolling app totals, latest app-model evidence and the producer-selected matrix as separate sections.

dashboard_matrix

Read the published app-model matrix while preserving approval-pending, collection-disabled, unavailable and observed states.

dashboard_github_movers

Return category-scoped project-family momentum for exact 7-, 30- or 90-day baselines.

dashboard_github_trending

List GitHub trending repositories with collection time, source path and a six-hour stale flag.

dashboard_key_inventory

Opt-in liveness and spend visibility for configured provider keys. It returns secret names only; values are never returned, logged or modified.

dashboard_contract

Return the 1.0 schema version, installed package version and deprecations, including replacements or an explicit reason when a capability is going away.

dashboard_speed

Show attributed published speed claims and the four-run streaming probe protocol: discard the first run, then publish TTFT and sustained tokens per second as median plus range.

Current provider shape

The registry intentionally preserves asymmetry. “Not published” means the provider did not give the field to the source; it never means zero or free.

Sail’s catalogue publishes model ids, not programmatic prices. The server parses pricing.md only when its digest matches the pin, and carries the completion window (ASAP, Balanced or Flex) with each input, cached and output point.

A model has a set of prices

The 1.0 contract removes the old scalar pricing fields. A point is an exact decimal amount, one of the measured billing units, a discriminated condition or null, a URL plus read date, and one of published, derived, parsed_from_prose or unknown.

Conditions

Never flatten the qualifier

Sail uses latency_window; Crazyrouter uses time_band with Asia/Shanghai hours and tier; fal GPU SKUs use rate_class for list versus as-low-as.

Comparison

Compatible or refused

Comparisons show both sides and every compatible condition. Per-image versus per-second, or mismatched windows, is refused rather than coerced.

Normalisation

Assumptions travel with numbers

Derived figures have value, unit, assumption and derived_from. Without an assumption, the native unit remains visible.

Speed is evidence too

The speed surface keeps published claims apart from our measurements. Its probe fixes the prompt and max_tokens=700, streams four runs, discards run one, and reports TTFT plus sustained TPS as median and range for the remaining three from one named vantage point.

Cerebras’ approximately 3,000 tokens/s and Groq’s 8,000 tokens/s are published claims, not measurements. The retained Cerebras real-call record is 867 / 1,022 / 1,108 tokens/s across three runs dated 2026-08-28; its exact time, vantage point and prompt hash were not retained, so those fields remain unknown. An unknown measurement stays unknown; a published ceiling is never presented as a caller quota.

Vantage

A latency without an origin is wrong, not partial

Latency is a property of a provider and a vantage point, so measured_from carries a location and a date on every measurement. Measured 2026-09-08, api.sailresearch.com answered in 56 ms from inside Sail’s own AWS Oregon network and 1,006 ms from Sofia — eighteen times, same endpoint, same minute. Sail is single-homed in Oregon; Groq, Cerebras and OpenRouter sit on Cloudflare’s edge. An unattributed figure silently favours whoever is nearest the benchmarking host.

Parity

Equal is a result

The surface reports parity when the runs show parity. Measured TTFT on gpt-oss-120b was 0.319 s on Cerebras and 0.335 s on Groq — a 5% gap, with Groq’s best run ahead of Cerebras’. A surface that can only express advantage will manufacture one.

Token basis

Which tokens were counted

Sustained TPS carries token_basis: visible_output or billed_total. Reasoning models make the two disagree by multiples — gpt-oss emits roughly two thirds of its tokens as reasoning that never reaches content, so a visible-output rate understates by about 3x while a billed rate measures what the caller never sees. Without a stated basis the figure is withheld rather than published.

Serviceability

Listed is not served

listed_but_unserviceable is its own state, distinct from slow and from absent. Sail lists gpt-oss-120b and, measured 2026-09-08, timed out at 45 s on a 32-token request, confirming a hypothesis left open on 2026-09-02. A provider listing a model it cannot serve is reportable as exactly that.

Contract changes announce themselves

dashboard_contract returns schema_version, package_version and deprecations[]. Each notice names the field being retired, removed_in, replaced_by or a plain reason, and since. A known removal without a reliable release date is unknown, never a guess.

Version 1.0 is the first release with this mechanism, so it could not preannounce its own 0.9-to-1.0 removals. That retrospective exception is stated once in the release notes; future removals are announced before the release that removes them.

Choose at install time

Set OPEN_DASHBOARD_TOOLS and OPEN_DASHBOARD_PROVIDERS before the server starts. Deselected tools are absent from tools/list; deselected providers are absent from provider-bearing responses, rather than appearing as empty catalogues.

Freshness is part of the answer

The server reads the public zero-credential API at query time. The default host is a hobby-tier deployment with no uptime guarantee, so failure and age are returned as structured state.

Live

Read now

Use cache: { "ttlMs": 0 }, or disable the cache with cache: false when the question needs a fresh upstream read.

Cached

Fast repeat

The default cache TTL is five minutes. Each evidence item includes fetchedAt, ageSeconds and expiresAt.

Expired

Last known, marked

If the upstream is unreachable but an older value exists, it is returned as expired with a note. With no value, the tool says unavailable.

Point the server at a compatible deployment with DASHBOARD_BASE_URL. It never silently substitutes a number whose freshness or provenance it cannot establish.

Three sharp edges, made visible

These are the details most likely to be flattened into a misleading “cheapest” or “nothing changed” answer. The package keeps them attached to the evidence.

Discounts

Endpoint fact, not model fact

Measured 2026-08-19: 0 of 550 OpenRouter model rows exposed a discount, while 272 of 272 provider endpoints did. No expiry is published, so expiresAt stays null.

Change detection

Empty is not all-clear

dashboard_whats_changed compares the two latest archived runs. Price movement and “stopped being free” stay in their own bucket, and successful coverage remains partial when the span cannot be established.

Sail

The document is the evidence

Sail prices come from a SHA-256-pinned pricing.md, not an API. If the digest moves, prices go quiet until the pin is reconciled; ASAP, Balanced and Flex remain distinct conditions.

Boundaries worth keeping

Unknown ≠ free

Unpriced models stay in the response as cost-unknown. A concrete zero price, a free router tier and an absent price are three different states.

No signal ≠ no risk

Groq, Cerebras and Sail do not publish the same lifecycle evidence as OpenRouter. The server reports that absence instead of calling it safe.

GitHub time is collection time

Trending data carries the origin collection timestamp, the path that served it and whether it has crossed the six-hour staleness boundary.

Read-only by construction

The server does not switch models, write configuration, mint credentials or rotate keys. An agent may use the evidence to make a decision; the server does not make the change.

The matrix has its own boundary

The site’s Matrix page visualizes the same latest-complete app-model evidence used by dashboard_usage_leaders. It is a top-10 slice for one published period, not a complete app census or a causal attribution.

When the source returns approval_incomplete, collection_disabled or another unavailable state, the page keeps that reason visible. Archived fixture data is explicitly labelled as a snapshot and is never mixed with live rows.

Not in this release

Automated switching

Deliberately outside the server. The intended writer is the agent or your own deployment configuration.

Task-quality fitness

Structural constraints are available; actual “good enough for this task” quality is not modelled.

Migration notice

Version 1.0 introduces deprecation notices. It could not pre-announce its own 0.9 to 1.0 removals; that retrospective fact is stated once in the release notes. Future removals are announced before the release that removes them.
