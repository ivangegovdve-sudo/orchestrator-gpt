Codex compatibility & help

This local stdio setup works with Codex in the desktop app, CLI or IDE. They share MCP settings when running on the same host. Add the generated entry to ~/.codex/config.toml there, then restart the connection or open a new session.

Install Node.js 20+ where Codex runs. Check node --version and npx --version in that environment. If a command is missing, add Node/npm to that host’s PATH and restart Codex. Choose Native Windows for cmd /c npx; choose WSL when Codex runs inside Linux, with Node and the config file inside WSL.

Web and hosted cloud sessions do not inherit this local setup. Open Dashboard does not currently provide a hosted connector. Use codex mcp list to check the saved entry and /mcp in the local app or CLI to check available tools.

What do I need before connecting?

Install Node.js 20 or newer with npm, and use an agent that supports local MCP servers. Your agent starts the pinned npm package through npx. Public model discovery and public usage tools do not need your provider keys; some provider sources and optional account tools need additional configuration. Check the package documentation for those sources.

Can I add or remove tools later?

Yes. Return to this page, choose your tools again, and replace the Open Dashboard entry in your agent’s settings. Restart the connection so it discovers the new selection. The OPEN_DASHBOARD_TOOLS setting controls which tools the server exposes. Omitting it exposes all 16.

Can this tell me when free models become paid?

It can report observed free-to-paid changes between archived OpenRouter runs. It does not predict a future price change, send alerts or monitor your personal usage allowance. The explorer shows provider free-plan limits separately from model prices.

dashboard_free_models
Models with confirmed zero prices and capability filters.
dashboard_price_comparison
Crazyrouter aliases compared with OpenRouter and sourced reference prices.
dashboard_model_status
Last observed availability for a model ID.
dashboard_whats_changed
Observed model and price changes between archive runs.

The published app-by-model usage matrix, when available.

The GitHub trending board and repository links.

Speed evidence, publication state and measurement protocol.

Data freshness and source availability.
dashboard_contract
Package version, schemas and announced removals.
